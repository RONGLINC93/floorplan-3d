# 2026-11-22 工作日志

## 多层楼编辑功能（v1.0.20 开发中）

架构决策：采用「当前层工作副本」方案，不改 20+ 个现有渲染/编辑函数。
- `state` 顶层数组始终是当前层的"视图"，其它层存 `state.byFloor[floorId]`。
- `state.floors` = [{id,name,z(标高mm),h(层高mm)}]，`state.activeFloor` 为当前层 id。
- 切层 = `packActiveFloor()` 归档顶层 → 展开目标层到顶层；`snap()`/`serializePlan()` 保存前自动归档。
- `FLOOR_KEYS` 列出所有按层保存的字段；轴网 axes / 电梯 lifts 为整栋共享，不在按层列表（电梯靠自身 floors[] 同步到各层标高）。
- `fixState()` 把老方案（无 floors）迁移为单层 1F。

楼层条 UI：`#floorBar`（画板顶部居中），切层 / ＋新增 / 复制整层 / 删除 / 层高输入（1200~12000mm）。快捷键 Ctrl+1~9 直达层、PageUp/PageDown 上下层。

层高联动：`roomCeilMM()` 默认层高改用 `currentFloorH()`；`recalcFloors()` 按 h 累加 z；`syncLiftsToFloors()` 把电梯各层停靠高度同步到楼层标高。

3D：当前层几何仍在 y=0（漫游/碰撞不动），其它层用 `buildFloorPlates()` 画半透明楼板示意，按 `(f.z - active.z)/1000` 偏移；`H` 由 const 改 let，`sync()` 里设为当前层高/1000；`onFloorChanged()` 暴露到 View3D 供切层强制重建。

改动文件：`index.html`（已同步 `app/www/index.html`）、`CHANGELOG.md`。浏览器实测：增删复制删除层、层高设置、切层数据隔离、撤销重做、老方案加载、3D 进入与切换、保存往返、Ctrl+1 快捷键，全部通过、零控制台报错。
